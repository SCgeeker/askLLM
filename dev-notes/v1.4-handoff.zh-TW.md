- `.h.R` 一律由 `jmvtools::prepare()`／`install()` 重生（S2），cloud 端不手改；每次 a.yaml 有變動時本機都要重生。

## 推送 3：v1.4-C「Show what will be sent」預覽 + 高基數／PII 防護

**改動**
- `R/data-summary.R`：識別碼型守門 `.askllm_identifier_like(k, n)`（k > 20 且 k/n > 0.9）——character／factor 欄符合時只回報「k distinct (identifier-like; values withheld)」，不列任何值（現況缺口：`Name` 欄會把前 10 個人名送進 prompt）。新增 `.askllm_pii_flags(df, vars)`：欄名整詞／分節規則（id、name、email、phone、address、姓名、學號……）+ 值樣式（email／電話 ≥ 50%）+ 識別碼基數，回傳 `var (reason)` 字串向量。
- 兩個 a.yaml 新增 `previewPayload` Bool（title「Show what will be sent (no LLM call)」，default false）；u.yaml 在 testConnection 前加 CheckBox。
- `askllm.b.R`／`askllmr.b.R`：預覽旗標不受 submit 守門限制；摘要／catalog／rj／自訂 prompt 照常組裝，在 payload 組好、**快取比對之前**提前 return：answer（或 code）面板顯示 `.askllm_preview_text(system, user)` 原文，meta 顯示「preview only · 0 API calls」，instructions 顯示零呼叫聲明 + 字元數 + PII 提示。不動 state、不載金鑰、不呼叫。
- `.askllm_caveat_text(has_catalog, pii_flags=NULL)`、`.askllmr_caveat_text(has_rj_env, pii_flags=NULL)`：有旗標時附雙語「疑似個資」區塊；NULL/空時逐字不變（既有測試鎖）。成功回覆後兩分析都會帶 PII 提示。
- guide 文字兩分析各加一句預覽說明；README 兩語版 Quick start 與 Privacy 各加段落。
- 測試：`tests/testthat/test-pii.R`（新，離線）：守門邊界、字元／factor／ordered 不列值、多水準類別不受影響、iris 回歸鎖、PII 欄名／值樣式／基數、iris/mtcars 零旗標、預覽文字、caveat 降級保證、a/u.yaml 選項、`.runInner` 原始碼掃描（預覽分支在快取比對前且不呼叫 ask_llm）。

**本機驗證清單**
1. `jmvtools::prepare()` 重生 `.h.R`（新增 previewPayload）；`devtools::test()` 預期全綠。
2. GUI（兩分析各一次）：勾「Show what will be sent」但**不勾 Submit** → 面板顯示 system/user prompt 原文、meta「preview only · 0 API calls」；供應商後台確認零用量。
3. GUI：預覽 + Submit 同時勾 → 仍是預覽（不送）；取消預覽 → 正常送出；再勾預覽 → 之前的回覆不被清掉（預覽不動 state），取消預覽後 cached 回放。
4. GUI：資料含 `Name` 欄（每列不同）→ 預覽中該欄顯示「values withheld」且 instructions 出現「Possible personal data」旗標；Submit 後 caveat 也帶旗標。
5. 對照 golden 基線：`run_golden(provider='gemini')` 分數不應因本推送改變（prompt 內容未變，只有識別碼欄摘要格式在含 ID 欄時不同；golden 資料集皆無識別碼欄）。
